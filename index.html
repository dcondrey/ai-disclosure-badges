Does this badge need to say something different about the code versus the description?

Most PRs, commits, and docs are one badge covering the whole contribution. Split only when the two genuinely differ — e.g. the code is human-written but the PR description was AI-drafted.

One question at a time, starting from human-only. Answer No and you stop there — that's your badge. Answer Yes and you move one step further toward fully AI-authored and unreviewed. Changed your mind? Use ← Back at any point.

Optional note on human involvement

The badge says whether AI was involved — it says nothing about how much a human steered the work. This note is the place for that: what you reviewed, or what you directed — rejected drafts, set the approach, redirected architecture, corrected a wrong turn. E.g. "reviewed for factual accuracy," "AI drafted, human rewrote throughout," or "human set requirements and rejected the first approach; AI implemented the revision." This is not part of the W3C specification's controlled vocabulary — it's a plain-language note carried in the badge's title/alt text, not a new disclosure category.
